# ШАГ 4.5. РАЗБОР: ДДЧЧМ, ВВВВ, БББ

## Зачем этот шаг

Шаги 5–7 предполагают, что ты уже умеешь собирать метеобюллетень из кусков.
Но в курсе не было нормального объяснения `to_char`, `extract`, `lpad`, `case`
и того, почему бюллетень — это строка, а не число.

Это пробел курса, а не твоя вина. Здесь всё разложено с нуля.

После этого шага ты должен уметь:

- собирать `ДДЧЧМ` из даты и времени;
- делать `ВВВВ` из высоты;
- кодировать `БББ` из давления;
- понимать, как эти куски превращаются в функции из ДЗ.

---

## 0. Главная идея: бюллетень — это строка фиксированной длины

Метеобюллетень — это не одно большое число. Это набор полей, у каждого
из которых своя длина. Поэтому в SQL мы работаем не с математикой числа,
а со строками и форматированием.

| Поле | Длина | Что внутри | Пример |
|---|---:|---|---|
| `ДДЧЧМ` | 5 | день (2), часы (2), десятки минут (1) | 24.10.2026 09:37 → `24093` |
| `ВВВВ` | 4 | высота метеопоста в метрах | 60 → `0060` |
| `БББ` | 3 | отклонение давления от 750 | 743 − 750 = −7 → `507` |
| `ТТ` | 2 | отклонение температуры | +11 → `11`, −13 → `63` |

`24093` — это не число `двадцать четыре тысячи девяносто три`. Это строка:

```text
24 | 09 | 3
```

Поэтому дальше мы будем использовать `||` (склейку строк) и `lpad` (добавление
нулей), а не `+` и `-`.

---

## 1. SQL-запрос может быть калькулятором

Тебе не нужны таблицы. Можно написать:

```sql
select 2 + 2 as result;
```

Результат:

```text
result
------
4
```

`select` — «выведи». `as result` — имя столбца в результате.

Можно проверить любое выражение:

```sql
select 743 - 750;
```

```text
-7
```

Это основа всех заданий: сначала считаем число, потом форматируем его в строку.

---

## 2. Строки и склейка

Строка в SQL пишется в одинарных кавычках:

```sql
select '24093';
```

Склейка строк — оператор `||`:

```sql
select '5' || '07' as result;
```

Результат:

```text
507
```

Важно:

- `'5'` — строка;
- `5` — число;
- `'5' || '07'` — склейка строк;
- `5 + 7` — сложение чисел.

В PostgreSQL `+` не склеивает строки.

---

## 3. Приведение типов: `::text` и `::int`

SQL различает числа и строки. Иногда нужно явно указать тип:

```sql
select 60::text;   -- число 60 → строка '60'
select '37'::int;  -- строка '37' → число 37
```

Зачем это нужно:

- `lpad` работает со строками, поэтому число нужно превратить в `text`;
- `extract` возвращает `numeric`, а для десятков минут нужно целое деление,
  поэтому нужен `::int`.

---

## 4. ДДЧЧМ: день, часы и десятки минут

Дано: `24.10.2026 09:37`.
Нужно: `24093`.

### Шаг 1. День и часы

`to_char` форматирует дату в строку:

```sql
select to_char(timestamp '2026-10-24 09:37', 'DDHH24');
```

Результат:

```text
2409
```

Расшифровка формата:

- `DD` — день месяца, две цифры: `24`;
- `HH24` — часы в 24-часовом формате, две цифры: `09`.

### Шаг 2. Минуты

`extract` достаёт отдельную часть даты:

```sql
select extract(minute from timestamp '2026-10-24 09:37');
```

Результат:

```text
37
```

### Шаг 3. Десятки минут

Нам нужна не минута `37`, а количество десятков: `3`.

```sql
select extract(minute from timestamp '2026-10-24 09:37')::int / 10;
```

Результат:

```text
3
```

Почему `::int`?

- `37 / 10` без приведения типов даёт `3.7`;
- `37::int / 10` — целочисленное деление, даёт `3`.

### Шаг 4. Склеиваем

```sql
select to_char(timestamp '2026-10-24 09:37', 'DDHH24')
       || (extract(minute from timestamp '2026-10-24 09:37')::int / 10)::text
       as ddchchm;
```

Результат:

```text
24093
```

Что произошло:

1. `to_char(...)` → `'2409'`;
2. `extract(...)::int / 10` → `3`;
3. `3::text` → `'3'`;
4. `'2409' || '3'` → `'24093'`.

## 5. ВВВВ: высота четырьмя цифрами

Дано: высота `60`.
Нужно: `0060`.

`lpad(строка, длина, чем_дополнить)` добавляет символы слева:

```sql
select lpad('60', 4, '0');
```

Результат:

```text
0060
```

Если высота — число, сначала приводим к строке:

```sql
select lpad(60::text, 4, '0') as vvvv;
```

Ещё примеры:

```sql
select lpad('7', 2, '0');   -- 07
select lpad('5', 3, '0');   -- 005
select lpad('123', 5, '0'); -- 00123
```

Важно: `lpad(60, 4, '0')` может не сработать, потому что `60` — число.
Пиши `60::text`.

---

## 6. БББ: отклонение давления

Дано: давление `743`.
Нужно: `507`.

### Шаг 1. Считаем отклонение

```sql
select 743 - 750;
```

Результат:

```text
-7
```

### Шаг 2. Убираем минус

```sql
select abs(743 - 750);
```

Результат:

```text
7
```

`abs` — модуль числа.

### Шаг 3. Дополняем до двух цифр

```sql
select lpad(abs(743 - 750)::text, 2, '0');
```

Результат:

```text
07
```

### Шаг 4. Добавляем пятёрку для отрицательного значения

```sql
select '5' || lpad(abs(743 - 750)::text, 2, '0');
```

Результат:

```text
507
```

### Полный запрос с проверкой знака

```sql
select case
           when 743 - 750 < 0
               then '5' || lpad(abs(743 - 750)::text, 2, '0')
           else lpad((743 - 750)::text, 3, '0')
       end as bbb;
```

Результат:

```text
507
```

`case` читается так:

- `when 743 - 750 < 0` — если отклонение отрицательное;
- `then ...` — сделай одно;
- `else ...` — иначе сделай другое;
- `end` — конец условия.

Для положительного отклонения:

```text
743 → -7 → 507
757 → +7 → 007
765 → +15 → 015
```

## 7. ТТ: отклонение температуры (бонус)

В полном заголовке `БББТТ` после давления идёт температура.
Правило похожее:

1. `T0 = t0 + ΔTv`, где `ΔTv` берётся из таблицы температурной поправки;
2. `ΔT = T0 - 15.9`;
3. округляем до целого;
4. если `ΔT` положительное — две цифры: `9 → 09`, `11 → 11`;
5. если отрицательное — `50 + модуль`: `-13 → 63`, `-12 → 62`.

Пример из ТЗ:

```text
давление 765, температура 25
ΔTv(25) = 2.0
T0 = 25 + 2.0 = 27.0
ΔT = 27.0 - 15.9 = 11.1 → 11
БББ = 015
ТТ = 11
БББТТ = 01511
```

В ДЗ это уже завёрнуто в функцию `meteo_bbbtt`.

## 10. Частые ошибки

1. **Плюс вместо `||`**

   ```sql
   select '5' + '07'; -- не склеит строки
   ```

   Для строк нужен `||`.

2. **`lpad` с числом**

   ```sql
   select lpad(60, 4, '0'); -- может быть ошибка
   ```

   Нужно `60::text`.

3. **Забыли `::int` при делении**

   ```sql
   select 37 / 10; -- 3.7, а не 3
   ```

   Нужно `37::int / 10`.

4. **Двойные кавычки**

   ```sql
   select "24093"; -- это поиск столбца с именем 24093
   ```

   Строки — в одинарных кавычках: `'24093'`.

5. **Нет `;` в конце**

   В psql/pgAdmin лучше всегда ставить `;`.

## 11. Как это связано с ДЗ

В `home_work_six.sql` те же выражения завёрнуты в функции:

- `meteo_ddchchm(...)` — ДДЧЧМ;
- `meteo_vvvv(...)` — ВВВВ;
- `meteo_bbbtt(...)` — БББТТ.

Если ты понял этот шаг, то функции читаются так:

```text
meteo_ddchchm = to_char(...) || (extract(...) / 10)
meteo_vvvv    = lpad(...)
meteo_bbbtt   = БББ + ТТ
```

То есть в ДЗ нет ничего нового по сравнению с заданиями 4.3–4.5.
Просто те же куски собраны в функции, чтобы их можно было вызывать из запросов.
